# 第 1 轮：纯文本不再同时保存 Data 和 searchText

假设：纯文本条目的 `data` 就是 `searchText` 的 UTF-8。列表和搜索结果把两份都留在 `ClipboardItem` 里。只留字符串，读取 `data` 时再编回同样的 UTF-8，搜索顺序和字节不变，堆占用下降。

改动：`Deck/Models/ClipboardItem.swift`。`searchText` 被改写时先把原来的 UTF-8 固化回去，避免数据跟着新文本变。

正确性：10 个场景哈希与持久化哈希都与第 0 轮一致。条数不变。

内存与性能（三次中位数）：

- 加载物理足迹 18.39 MiB → 17.45 MiB（-0.94 MiB，-5.1%）；峰值同样；延迟 253.48 ms → 254.8 ms（+0.5%）
- 模糊搜索物理足迹 30.39 MiB → 28.14 MiB（-2.25 MiB，-7.4%）；堆 13.48 MiB → 11.27 MiB（-2.21 MiB，-16.4%）；延迟 64.96 ms → 62.4 ms（-3.9%）
- 混合模糊物理足迹 30.58 MiB → 28.39 MiB（-2.19 MiB，-7.2%）；堆 13.48 MiB → 11.27 MiB（-16.4%）；延迟 78.99 ms → 76.2 ms（-3.5%）
- 英文语义堆 8.56 MiB → 7.37 MiB（-1.19 MiB，-13.9%）；延迟 18.40 ms → 17.0 ms（-7.6%）
- 维护峰值 90.86 MiB → 90.81 MiB（在噪声内）

结论：保留。
